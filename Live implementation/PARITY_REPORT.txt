SmartGlove ESP32 deployment parity report
==========================================

Frozen model:
- F5_NEUTRAL_FLEX_STATIC_IMU
- StandardScaler
- Logistic Regression, C=10
- 12 features
- 10 gesture classes

Verification performed before packaging:
1. Loaded the supplied final_model_bundle.joblib.
2. Exported scaler mean/scale, 10x12 Logistic Regression coefficients,
   10 intercepts, and class order to float32 C++ constants.
3. Evaluated float32 ESP32-style scaling + linear class-score inference on
   all 500 archived F5 feature rows.
   RESULT: 500 / 500 predicted labels matched the scikit-learn pipeline.
4. Recomputed the F5 features from all 500 raw accepted 50-sample trials
   with ESP32-style float arithmetic, using the matching session calibration.
   Maximum absolute feature discrepancy versus the saved training F5 table:
   approximately 1.21e-4.
5. Passed those recomputed features through the exported float32 model.
   RESULT: 500 / 500 predicted labels matched the scikit-learn pipeline.

Interpretation:
- The exported scaler/model constants preserve the trained classifier decisions
  on the complete archived dataset.
- The feature implementation is numerically close to the training Python
  implementation and produced identical archived-dataset predictions.
- Live-user accuracy is still a separate prospective question; this parity
  check verifies implementation consistency, not new-user performance.

Important limitation:
The exact final V3.1.2 acquisition source was unavailable. The live firmware
therefore preserves the known acquisition settings from the available V3.1.0
source and uses the final dataset/training definitions as authority for F5.
